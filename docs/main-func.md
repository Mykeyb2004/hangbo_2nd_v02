# 代码库主要功能说明

## 1. 项目定位

该项目是一个基于 Next.js 15 + React 19 的问卷统计报告站点，用于展示“杭州国际博览中心二期（测试）展会体验与服务反馈”结果。它的核心目标不是在线采集问卷，而是把已经整理好的问卷统计结果，以月报形式展示成可切换、可筛选、可发布的可视化报告页面。

---

## 2. 主体功能

### 2.1 问卷统计报告展示

前端首页会加载一份报告数据，并将其渲染为完整报告页面，主要包括：

- 报告标题、期数、生成时间、样本量等元信息
- 顶部摘要指标卡（highlights）
- 按章节组织的问卷结果展示
- 右下角快速导航，便于跳转到对应章节
- 页脚品牌信息

当前问卷内容主要覆盖：

- 受访者身份、性别、年龄等基础信息
- 总体满意度、预期达成度、再次参加意愿
- 到达与入场体验、场馆环境、现场管理等矩阵评分题
- 按不同身份分支展示的展会体验题
- 针对“测试状态”的专项问题感知与影响评价
- 待提升方向与开放建议

### 2.2 按客群筛选统计结果

页面支持按照受访者身份切换统计视角，例如：

- 参展商
- 专业观众
- 普通观众
- 展会服务商/搭建商/物流商
- 主办方/协办方工作人员
- 其他

筛选后，题目统计会同步切换到对应客群口径。整体上这是一个“同一份报告，多客群视角复用”的展示系统。

### 2.3 按月份查看历史归档报告

系统支持从 `data/reports/YYYY/MM.json` 中读取归档数据，并通过 URL 参数切换期数，例如：

- `/?year=2026&month=03`

当用户未指定期数，或指定的年月不存在时，系统会自动回退到最新一期归档报告。如果不存在归档目录，则回退到 `data/report-data.json` 这份默认报告。

### 2.4 多题型统计可视化

前端并不只输出纯文本统计，而是针对题型提供不同展示方式：

- 单选题、多选题：柱状图 + 统计表
- 评分题：均值、8-10 分高分占比、分布
- 矩阵评分题：子项评分卡 + 雷达图
- 分支矩阵题：按适用身份分别展示
- 开放题：当前只展示填写率，不展示原始文本

因此该项目本质上也是一个轻量的问卷数据可视化前端。

### 2.5 问卷章节化编排与导航

问卷内容按 section 固定编排，当前主要分为：

- 受访者信息
- 总体体验评价
- 关键环节满意度评价
- 针对测试状态的专项评价
- 评价或建议

页面内部提供章节卡片和快速导航，便于在长报告中快速定位。

### 2.6 适用样本控制

项目对逻辑跳转题做了专门处理。像 Q15/Q16/Q17 这种仅适用于部分身份的题目，不会混入总体全样本统计，而是只在适用人群范围内计算，避免口径错误。

## 3. 数据处理功能

### 3.1 Excel 问卷原始数据离线解析

项目保留了从 Excel 原始问卷导出文件生成报告 JSON 的能力。`scripts/build_survey_report_data.py` 会读取：

- `data/data.xlsx`
- `outputs/survey_field_mapping.csv`

并产出前端可直接消费的 JSON 报告数据。

这一步是离线执行的，不在浏览器端完成。

### 3.2 字段映射自动生成

`scripts/generate_survey_field_mapping.py` 会解析 Excel 表头，识别：

- 哪些列属于问卷题目
- 题目编号和题组
- 字段类型（单选、多选、10 分制、开放题、元数据）
- 是否建议纳入分析
- 字段适用范围

这让项目可以在 Excel 表头变化时，半自动维护映射关系，而不是完全手工对列。

### 3.3 统计聚合与口径规范化

离线脚本会把原始答案转换成统一统计结构，主要包括：

- 单选题选项分布
- 多选题 one-hot 选中人数统计
- “其他”文本补充人数统计
- 评分题均值与高分占比
- 缺失值统计
- 按客群拆分的 `statsByAudience`

同时还做了一些规则清洗，例如：

- 仅保留 1-10 的评分值
- 跳过联系方式、提交时间、审核任务 id 等元数据列
- 开放题不直接输出原文
- 分支题按适用客群统计

### 3.4 报告结构固化

前端展示的章节与题目顺序，不是完全由 Excel 自动推导，而是由 Python 脚本中的 `SECTION_SPECS` 固定定义。这意味着：

- 统计口径更稳定
- 报告展示结构可控
- 若新增题目，需要同步补充脚本结构定义

---

## 4. 前端交互与展示能力

前端层的主要职责不是算数据，而是消费聚合后的 JSON 并提供报告交互，包含：

- 客群筛选切换
- 年份 / 月份报告切换
- 长页面章节导航
- 题型分发渲染
- 图表与统计卡片展示
- 报告骨架、头图、摘要区、页脚等整体编排

因此该仓库的前端更接近“报告阅读器 / 可视化壳层”。

## 5. 构建与发布功能

### 5.1 本地开发

项目可直接通过：

```bash
npm run dev
```

启动前端开发环境。开发时默认读取现成 JSON，不会自动重新跑 Python 数据生成。

### 5.2 手动刷新报告数据

如需从 Excel 重新生成报告，可执行：

```bash
uv run python scripts/build_survey_report_data.py
```

这符合仓库约定的 Python 运行方式。

### 5.3 生产构建与独立打包

项目支持：

- `npm run build` 进行 Next.js 构建
- `npm run bundle` 生成可部署的 `dist/`
- `npm run bundle:archive` 打包成 `dist.tar.gz`

打包结果会带上：

- Next.js standalone 服务端输出
- 静态资源
- `public/`
- `data/report-data.json`
- `data/reports/`

也就是说，该仓库具备“报告站点独立部署包”产出能力。

---

## 6. 总结

该代码库的主要功能可以概括为四类：

1. 展示按月份归档的问卷统计报告
2. 支持按受访客群切换统计视角
3. 通过 Python 离线脚本把 Excel 问卷结果聚合为前端 JSON
4. 将报告站点构建并打包为可独立部署的产物

如果从系统角色看，它不是“问卷填写系统”，而是“问卷统计报告生成与展示系统”，其中：

- Python 脚本负责离线清洗和聚合
- Next.js 前端负责报告呈现和交互
- `data/reports` 负责报告归档与期数切换
